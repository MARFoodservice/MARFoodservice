# Repositório MAR Food Service

## Boas Práticas para Criação de Repositórios ☕️

Cada projeto deverá possuir um repositório próprio, garantindo a organização, rastreabilidade e manutenção adequada do código-fonte.

O repositório deve conter todos os artefatos necessários para o funcionamento e manutenção do projeto, incluindo:

* Código-fonte do backend (Java, Python ou outras tecnologias utilizadas);
* Aplicações frontend (HTML, CSS, JavaScript, entre outros);
* Arquivos de configuração;
* Documentação técnica do projeto, preferencialmente em um arquivo `README.md`, `Documentacao.md` ou documento PDF.

A centralização desses recursos facilita a colaboração entre equipes, o versionamento e a continuidade do desenvolvimento.

---

## Privacidade dos Repositórios 🔒

Todos os repositórios deverão ser criados como **privados**, a fim de preservar informações estratégicas, códigos proprietários e dados relacionados à empresa.

A exposição indevida de informações pode representar riscos de segurança e conformidade. Caso um repositório seja criado como público por engano, sua visibilidade deverá ser alterada imediatamente para privada.

---

## Padrão de Identificação dos Repositórios 📁

Para facilitar a identificação e organização dos projetos, os repositórios deverão seguir o padrão de nomenclatura abaixo:

```text
nome-do-projeto-setor
```

### Exemplos

```text
portal-fornecedores-compras
integracao-rdstation-marketing
dashboard-indicadores-auditoria
api-faturamento-financeiro
```

O nome deve representar claramente o projeto e o setor responsável ou principal área de utilização da aplicação.
